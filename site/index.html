The landscape

Everyone is building upstairs.

The field looks crowded until you read it as a stack. Three floors make more sessions. One decides what a session may leave behind.

  1. Labor who does the work lists rule files
  2. Cockpit how a human watches many sessions lists rule files
  3. Distribution how capability reaches a session ships capability
  4. Governance what constrains any session, and who checks enforces

A plugin

distributes capability into a session.

A pack

distributes constraint into a repository — plus the files that repository then owns.

No install scope is repo-scoped: the project one reaches the repo but is advisory and locally switchable, and the managed one is enforced but follows a person to every repository they open. The gap between them is this floor.

How a rule stops being advice

A rule
graduates

Prose is where a rule starts, not where it ends. Promotion moves it down a ladder: each rung costs less attention and binds harder.

  1. prose every session the agent may apply it
  2. skill on demand the agent may apply it
  3. check no context it blocks
  4. hook no context the call never happens

Prose is rent. A check is equity. One is paid every session; the other is bought once and costs nothing until it fires.

The gate

It holds
twice

Once where the agent is, and once where it isn't.

  • When a session tries to stop — with the transcript in view, so rules about how the work was done are checkable too.
  • Again in CI, on every pull request, where no agent is present at all.
  • The finding is the instruction — what, why, and the fix. Blocking means the session does not end.

Two severities, and an advisory never fails anything. A rule that is wrong here is exempted on the record, with a reason — a reasonless exemption is itself a finding.

Convergence

The fleet
converges itself

Desired state, not an errand somebody owns — the Puppet model, pointed at conventions.

  • Every repo re-vendors the canon nightly. Nobody falls behind; nobody upgrades anything.
  • The difference lands as a pull request, gated by your own CI.
  • Upkeep runs on the repo's own schedule, each run with an outcome you can read.

That PR is also the supply-chain review: nothing reaches your repository except as a diff someone reads.

The loop that runs backwards

Lessons
travel

Every other loop here runs one way, from a registry into a session. This one also runs back — from the work into the constraint.

  • A correction becomes a rule in that repo, in a PR you review.
  • A rule that proves itself is promoted into the canon every repo reads.
  • Every repo inherits it by morning, through the same nightly convergence.

One repo meets the problem; the fleet is immune. The native equivalent is deliberately machine-local — learned notes are never shared between machines.

FAQ

Fair questions

What gets added to my repo?

A vendored canon, a declaration, hook entries, a scheduler workflow and a CI step — one PR.

Do I have to write the rules myself?

No. Packs arrive written, and the rest are mined from your own sessions — you review the PRs that land them.

Can I have rules that never leave this repo?

Yes — a local pack. Same prose, same checks, same machinery; it is simply never promoted.

Will it fight my CLAUDE.md?

No. It adds the layer that file can't carry, and keeps it lean.

Is my session transcript sent anywhere?

There is nowhere to send it. Captures are scrubbed of secrets and stay in your own repository.

What does it cost?

Nothing today — the canon is a public repository and there is no service to bill for.

Windows? Monorepos?

Node and shell hooks, so native Windows without WSL is unsupported; monorepos aren't addressed yet.

Is the chart real data?

No — it is schematic, and asserts no magnitudes. The shapes are the claim: a prose-only corpus saturates against the context budget, and promoting prose into checks keeps freeing it.

How do I leave?

Delete .claudinite/, its hook entries, the scheduler workflow and the CI step.
